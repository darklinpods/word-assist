# ADR 0003：文书能力采用类型化定义和注册表

- 状态：已接受
- 日期：2026-08-12

## 背景

旧应用按文本审查、索赔核定、证据核查和计算器组织页面。产品聚焦要素式起诉状后，继续在 `App.tsx` 和主页面中增加案由或文书类型会形成大量条件分支，也无法复用统一的读取和生成生命周期。

未来可能增加其他案由的要素式文本、送达地址确认书和授权委托书。

## 决策

- 使用 `DocumentDefinition<TDraft>` 描述文书的标题、提取、校验、目标检查和生成能力。
- 公共 `useDocumentGeneration` 只管理读取、提取、预览、生成、结果和错误状态。
- 每种文书拥有独立的结构化类型、提示词、校验、预览和 Word 生成适配器。
- 文书通过类型安全的 `registry.ts` 接入。
- 当前只注册交通事故要素式起诉状；不提前实现通用低代码表单引擎。

## 影响

- 优点：新增文书无需修改公共状态机，案由规则保持隔离。
- 代价：每种文书需要少量定义和适配文件。
- 约束：公共层不得引用特定案由字段或模板标签。
- 演进：只有在多个文书真实共享数据后，才引入公共 `CaseData`。
