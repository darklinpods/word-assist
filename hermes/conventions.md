# 工程约定

## 修改原则

- 保持 TypeScript 类型明确，避免用 `any` 绕过 Office 类型问题。
- 优先扩展现有模块，不在组件中直接堆叠 Word API 调用。
- 复用统一写入函数，避免同一种模板内容出现不同格式或同步行为。
- 错误信息使用用户能理解的中文，并说明需要检查的文档条件。

## Office.js 约定

- 进入 Word 功能前执行 `assertWordLoaded()`。
- 严格遵循 `load -> context.sync -> 读取`。
- 结构性操作（插行、合并、重新定位）后重新加载相关集合。
- 基础写入与增强格式分层处理：核心文本写入必须优先成功，可选格式能力允许降级。
- 捕获兼容性错误时只忽略已知的可选增强；不得吞掉核心写入、定位或数据错误。

## 模板格式约定

要素式诉状的自动填入内容当前采用：

- 字体：微软雅黑
- 字号：11 磅
- 字符宽度：85%
- 字符间距：0.25 磅

其中字符宽度和字符间距依赖 `WordApiDesktop 1.3`。不支持时保留文本、字体和字号，跳过高级格式。

## 验证约定

自动检查：

```bash
npm run build
npm run lint
```

涉及 Word 写入时，还应在 Word 桌面版手工检查：

1. 在已有正文的文档中插入模板，模板与原内容之间应分页。
2. 回填单个和多个原告、自然人被告、法人被告、保险公司及第三人。
3. 回填诉讼请求、事实与理由、索赔清单，确认目标单元格和格式。
4. 在不支持高级字体属性的宿主中，确认文本仍能成功写入。

## 文档约定

- 当前进行中的内容写入 `current.md`。
- 长期有效的系统事实写入 `project.md`、`architecture.md` 或本文件。
- 有取舍的重要决定新增 ADR，不事后改写旧 ADR；变化用新 ADR 取代。
