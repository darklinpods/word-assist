# 工程约定

## 修改原则

- 先明确行为边界，再修改实现；不要用 UI 隐藏代替删除废弃能力。
- TypeScript 保持严格类型，不用 `any` 绕过模型数据或 Office API 问题。
- 组件负责展示和交互，AI、领域规则和 Word 操作分别留在对应边界。
- 错误信息使用可操作的中文，说明用户需要检查的文档、配置或模板条件。
- 优先保留可靠的 Word 写入基础设施；当旧编排层与新产品流程冲突时，允许直接重写编排层。

## 文书模块约定

- 每种文书通过 `DocumentDefinition<TDraft>` 暴露提取、校验和生成能力。
- 文书 ID 使用稳定的 kebab-case，例如 `traffic-accident-elemental-complaint`。
- 文书专用代码放在 `src/document-generator/<document>/`。
- 公共 Hook 不引用案由字段、模板标签或特定预览组件。
- 新文书通过注册表接入，不在 `App.tsx` 中堆叠文书类型判断。

## AI 数据约定

- 提示词明确角色、固定字段、空值和互斥规则。
- 模型只输出 JSON；解析器对每个固定字段做运行时类型校验。
- 模型结果进入 UI 前完成确定性归类和去重。
- 不依赖提示词单独保证关键法律角色规则；关键规则必须有代码级兜底和测试。
- 不推断原文没有的信息；未识别字段以空字符串或空数组表示。

## 当事人角色约定

- 自然人被告、法人被告、保险公司被告、法人第三人使用独立集合。
- 法人车主、管理人和用人单位属于法人被告。
- 承保并承担保险责任的机构属于保险公司被告。
- 保险公司与法人被告互斥，统一社会信用代码优先用于去重，规范化名称作为后备。
- 新增角色归类规则必须提供至少一个正例、一个误分类例和一个重复例测试。

## React 约定

- 提取结果页面为只读展示，不使用 `input`、`textarea` 或编辑回调。
- 长列表或分区可折叠，但展开状态不能因父组件重渲染而意外重置。
- 窄任务窗格优先，标题、按钮和长文本必须允许收缩或换行。
- 由事件触发的异步逻辑放在事件处理器或 Hook 中，不用 Effect 模拟用户操作。

## Office.js 约定

- Word 功能入口先执行 `assertWordLoaded()`。
- 严格遵循 `load -> context.sync -> 读取`。
- 插行、合并或重新定位后重新加载相关集合。
- 核心文本写入和增强格式分层同步；可选格式允许降级，核心写入错误不得吞掉。
- 不静默覆盖已有文书；生成新版本前向用户说明行为。

## 模板格式约定

要素式诉状自动填入内容采用：

- 字体：微软雅黑
- 字号：11 磅
- 字符宽度：85%
- 字符间距：0.25 磅

字符宽度和间距依赖 `WordApiDesktop 1.3`。不支持时保留文本、字体和字号。

## 测试约定

每次交付至少执行：

```bash
npm run test
npm run build
npm run lint
git diff --check
```

修改 `manifest.xml` 时额外执行：

```bash
xmllint --noout manifest.xml
```

纯逻辑测试优先覆盖：

- AI JSON 成功和失败解析。
- 领域完整度和身份证校验。
- 当事人角色分类、误分类纠正和跨组去重。
- 结构化数据到模板写入格式的映射。

涉及 Word 写入时还需手工覆盖：单人、多当事人、已有模板、分页、高级格式支持和旧宿主降级。

## Hermes 文档约定

- `project.md` 保存长期产品边界。
- `architecture.md` 保存当前结构和数据流。
- `conventions.md` 保存施工规则和验证门槛。
- `current.md` 保存当前交付状态与未完成验证。
- 重要取舍新增 ADR；旧 ADR 不回写结论，变化通过新 ADR 取代。
