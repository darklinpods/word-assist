# 当前工作

更新时间：2026-07-29

## 工作区概况

当前正在实现面向普通律师的 AI 首次配置引导。此前的 Word 要素式诉状格式优化及 Hermes 初始化已经提交。

### AI 运行时配置引导

- 新增 `src/services/ai-config.ts`，负责读取、验证和保存每位用户自己的火山方舟配置。
- 运行时本地配置优先，开发模式的 `VITE_ARK_API_KEY` 与 `VITE_ARK_MODEL_EP_ID` 继续作为兼容回退；生产构建不读取开发者密钥。
- 新增 `src/components/AiSetup.tsx`：提供账号开通、API Key、推理接入点三步说明，并在保存前发起最小测试请求。
- 未配置时自动进入引导页；配置成功后进入主功能，右上角可随时修改。
- API 调用改为每次动态读取配置，修改配置后无需刷新或重新构建。
- 本机配置存储键使用带版本号的 `word-assist.ai-config.v1`。

### `src/utils/office/parties-template.ts`

- 新增统一的 `writeCellBody` 写入函数。
- 所有自动填入的标签和内容统一应用微软雅黑、11 磅、85% 字符宽度、0.25 磅字符间距。
- 将字体的基础能力与桌面版高级能力拆成两次同步。
- 当宿主不支持 `font.scaling` 或 `font.spacing` 时静默降级，确保文本及基础字体已经写入。
- 当事人行、诉讼请求、索赔清单和事实理由改为复用统一写入路径。
- 原先的 `applyElementalFont`（80% 字符宽度）被移除，字符宽度调整为 85%。

### `src/utils/office/template.ts`

- 接收 `insertFileFromBase64` 返回的插入范围。
- 在该范围之后插入分页符，使新模板与文档原有内容分处不同页面。

## 行为意图

- 模板自动回填后的视觉格式保持一致。
- 高级字体属性不可用时，不应导致完整回填失败。
- 插入到文档开头的模板不应与已有正文连在同一页。

## 待手工验证

- 使用真实有效、无效和余额不足的方舟凭证检查服务端错误提示。
- 配置成功后在真实 Word 宿主中执行各项 AI 功能。
- 在支持 `WordApiDesktop 1.3` 的 Word 桌面版确认缩放和字符间距实际生效。
- 在旧宿主确认高级格式失败不会影响文本写入。
- 确认分页符位于完整插入模板之后，不会在模板内部产生额外空白页。
- 覆盖多当事人动态插行及所有完整回填字段。

## 关注点

- 运行时凭证保存在插件域名的 `localStorage`，适合个人电脑的客户端直连模式，但不等同于服务端密钥保险库；团队正式部署宜使用后端代理和用户鉴权。
- “验证并保存”会产生一次极小的模型调用，界面必须保留费用提示。
- 当前对高级字体属性的 `catch` 不区分具体错误，只适合包裹可选格式设置；后续不要把核心写入逻辑移入该块。
- `writeCellBody` 每个单元格最多触发两次 `context.sync()`，可靠性优先但批量写入性能可能下降；若出现明显延迟，再评估批处理方案。
